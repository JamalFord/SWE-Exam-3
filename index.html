Standard UML State Transition Label: Event [Guard] / Action

1. SDLC, Ethics & Quality Attributes

  • SDLC: Software Development Life Cycle: Requirements → Design → Implementation → Testing → Deployment → Maintenance.
  • 4 P's: People, Product, Process, Project.
  • 4 Attributes of Good Software: 1. Maintainability (evolves with needs); 2. Dependability & Security (reliability, safety); 3. Efficiency (CPU, memory, response time); 4. Acceptability (usable, compatible).
  • Cost Distribution: ~60% Development, ~40% Testing. For custom products, evolution costs exceed dev costs!
  • ACM/IEEE Ethics: 1. Public, 2. Client & Employer, 3. Product, 4. Judgment, 5. Management, 6. Profession, 7. Colleagues, 8. Self.

2. Requirements Engineering

  • Functional: What system MUST do (services, reactions, inputs → outputs).
  • Non-Functional (NFR): Quality constraints (performance, security, portability, reliability).
  • Testability Trap: Subjective terms ("instantaneously", "user-friendly", "little training") must be rewritten into measurable metrics (e.g. "≤ 200ms latency", "≤ 2 errors per 8 hrs").
  • Use Case Relationships:
    • «include»: Mandatory sub-task; base use case is INCOMPLETE without it.
    • «extend»: Optional sub-task triggered at extension points; base is complete alone.

3. Kruchten 4+1 View Model & Architectural Styles

1. Logical View: Class diagrams, statecharts. End-user domain concepts.
2. Process View: Activity & Sequence. Concurrency, performance, scalability.
3. Development View: Packages, components. Programmers' code organization.
4. Physical View: Hardware nodes, network deployment topology.
+1 Unified View: Use Cases / Scenarios that tie the 4 views together.
Layered: UI → Business → DB. (+) Modular, portable. (-) Layer overhead.
Repository: Central DB + tools. (+) Efficient data sharing. (-) Single point of failure.
Client-Server: Distributed servers. (+) Scalable, network-ready. (-) Network latency/security.
Pipe & Filter: Unix stream filters. (+) Reusable transforms. (-) Overhead parsing formats.

4. Software Testing Definitions & Scaffolding

Verification: "Are we building the product RIGHT?" (conforms to spec).
Validation: "Are we building the RIGHT product?" (meets user needs).
Dijkstra's Axiom: Testing shows presence of bugs, NEVER their absence!
Test Scaffolding:
• Driver: Module calling the unit under test.
• Stub / Mock: Dummy module called by unit.
• Harness: Framework executing tests (JUnit).
• Oracle: Verifier comparing expected vs actual.
JUnit Lifecycle:
@Test: Test case method.
@Before / @BeforeEach: Runs before EVERY test.
@After / @AfterEach: Runs after EVERY test.
@BeforeClass / @All: Runs ONCE before suite.

5. UML Class Diagram Strict Rules

  • GOLDEN RULE: Any class drawn with 2 compartments is WRONG! Always draw 3 compartments: 1. Name, 2. Attributes, 3. Operations (leave blank if none).
  • Finding Classes: Nouns = Class; Noun Phrases = Attributes; Verbs = Operations.
  • Visibility: + Public | - Private | # Protected | ~ Package.
  • Relationships & Text Notations:
    • Aggregation <>-- : "has-a", open diamond at whole. Doctor outlives Department.
    • Composition <*>-- : "part-of", solid diamond at whole. LabTest destroyed if Department deleted!
    • Generalization --|> : "is-a", solid line with hollow triangle at parent.
    • Realization ..|> : implements interface, dashed line with hollow triangle.
    • Dependency ..> : uses, dashed line with open arrow.

6. Sequence, Activity & State Notations

  • Sequence Diagrams:
    • Synchronous call: Solid line, filled arrowhead ——▸
    • Asynchronous: Solid line, open arrowhead ——>
    • Return: Dashed line, open arrowhead <- - -
    • Fragments: alt (if-else), opt (if only), loop (while/for), par (parallel).
  • Activity Diagrams:
    • Fork: 1 incoming flow → 2+ concurrent parallel flows.
    • Join: 2+ incoming concurrent flows → 1 outgoing flow.
    • Swimlanes: Partitions indicating actor/system responsibility.
  • Statechart Transition Syntax:
    Event [Guard] / Action

7. Structural (White-Box) Testing, Coverage & MC/DC

Statement Coverage ($C_0$):
$\frac{\text{statements executed}}{\text{total statements}} \times 100\%$
Weakest! Misses untaken false branches in single if blocks.
Branch Coverage ($C_1$):
Every decision edge (True and False) traversed at least once.
Subsumption: Branch coverage subsumes Statement coverage!
MC/DC Coverage:
Avionics safety standard (DO-178C). Each condition must independently affect decision outcome with others fixed.
Test cases required: $n + 1$ (vs $2^n$ full).
Equivalence Partitioning (EP): Divide inputs into valid and invalid classes. Pick 1 representative per partition.
Boundary Value Analysis (BVA): Test edges of partitions ($min-1, min, min+1, nom, max-1, max, max+1$).

8. Relational Database & Normalization Summary

Integrity Rules:
• Entity Integrity: Primary Key cannot be null.
• Referential Integrity: Foreign Key must match valid PK or be null.
Normal Forms (1NF → 3NF):
• 1NF: Atomic values, no repeating groups.
• 2NF: 1NF + no partial key dependencies (attributes depend on full composite PK).
• 3NF: 2NF + no transitive dependencies (non-key attribute depends on another non-key).
"All attributes depend on the key, the whole key, and nothing but the key."
